- **Define the state in words first.** Say out loud what `dp[i]` means ("max money robbed using houses 0..i") before writing the recurrence — most bugs come from a fuzzy state definition, not the code.
- **Nail the base case(s) and the off-by-one.** Many of these problems need `dp[0]` *and* `dp[1]` seeded before the loop starts (Climbing Stairs, House Robber) — an unhandled empty or single-element input is a classic wrong-answer trap.
- **Roll the array down to variables.** If `dp[i]` only reads `dp[i-1]`/`dp[i-2]`, keep two or three scalars instead of a full array — O(1) space, and interviewers notice you did it.
- **Kadane's trick — reset vs extend.** For "best subarray ending here" problems, at each step decide: extend the running best, or start fresh at the current element (`cur = max(x, cur + x)`). The same shape solves Maximum Subarray and Maximum Product Subarray (the product version also needs to track the running *min*, because a negative can flip min to max).
- **Unbounded vs 0/1 choices matter.** Coin Change lets you reuse a coin (unbounded knapsack — iterate amounts outer, coins inner or vice versa depending on "ways" vs "min coins"); House Robber forbids reusing a house. Get this backwards and you double-count or under-count.
- **Memoization vs tabulation is a real trade-off.** Top-down memoization mirrors the recursive brute force and is easier to get right first; bottom-up tabulation avoids recursion-depth limits on large `n` — mention both if time allows.
- **Pitfall — integer overflow / negative products.** Track min *and* max running values when negatives can flip a sign (Maximum Product Subarray); a single running max silently gives the wrong answer.
- **Pitfall — circular constraints.** House Robber II's "houses in a circle" reduces to two linear House Robber runs (exclude last, exclude first) — recognizing the reduction beats reinventing DP for circular arrays.
