- **Dijkstra needs non-negative weights.** If negative weights are possible, or the problem caps the number of edges/stops (like "cheapest flights within K stops"), reach for Bellman-Ford or a K-relaxed BFS instead — Dijkstra's greedy pick can be wrong there.
- **Union-Find without the two optimizations is just a slow linked list.** Always pair **path compression** (`find` re-points every node on the way to the root) with **union by rank/size** (attach the smaller tree under the bigger). Skipping either still works but degrades toward O(n) per operation on adversarial input.
- **Kruskal's = sort edges by weight + union-find.** Walk edges smallest-first; union the endpoints only if they're not already connected. Stop early once you've added `n - 1` edges.
- **Topological sort needs a cycle check.** If Kahn's algorithm processes fewer than `n` nodes (some in-degrees never hit zero), the graph has a cycle and no valid ordering exists — a common trick to detect "impossible" cases (e.g., course schedule).
- **Track distances, not just visited sets, in weighted graphs.** A node can be reached multiple times at different costs — never mark a node "done" until you pop it from the min-heap with its true shortest distance.
- **Euler paths need a degree check first.** An Euler circuit exists only if every vertex has even degree (undirected) or in-degree equals out-degree (directed); an Euler path allows exactly one imbalance in each direction. Check this before running Hierholzer's — otherwise you can loop forever.
- **Pitfall — rebuilding the adjacency list per query.** For sparse graphs, build the adjacency list once as `map(node -> list of (neighbor, weight))`; a fresh scan of the edge list inside the main loop turns an O(E log V) algorithm into something much worse.
- **State the complexity trade explicitly:** Dijkstra with a binary heap is O(E log V); Bellman-Ford is O(V·E) but handles negative weights; union-find operations are ~O(α(n)), effectively constant — naming these shows you understand *why* you picked one over another.
