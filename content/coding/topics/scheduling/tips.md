- **Pick the sort key deliberately:** end time for "max non-overlapping" problems, start time for sweep-line room-counting, deadline for "finish everything on time," and cost-difference for two-way assignment (Two City Scheduling). The wrong key silently breaks the greedy proof.
- **Task Scheduler pattern:** a max-heap by remaining count plus a cooldown queue (or the closed-form `max(n, (maxFreq-1)*(k+1) + countOfMaxFreq)`) both solve it — know the heap version for follow-ups that add real constraints.
- **Binary search the DP transition:** in weighted job scheduling (Maximum Profit in Job Scheduling), sort by end time, then for each job binary-search the last job whose end ≤ current start — turns an O(n²) DP into O(n log n).
- **Sweep-line for "how many rooms":** split each interval into a `(start, +1)` and `(end, -1)` event, sort events (ends before starts on ties, to free a room before reusing it the same minute), and track the running max — no heap needed for the *count*; use a min-heap of end times only if you need to know *which* room.
- **Exchange argument, not intuition:** when a greedy order feels right but you're unsure, mentally swap two adjacent choices and check the result never gets worse — that's the proof interviewers want, even said aloud in one sentence.
- **Pitfall — off-by-one on "at most k":** cooldown/gap constraints (`k` slots apart) mean intervals of length `k+1`, not `k`; miscounting this is the most common bug in Task Scheduler-style problems.
- **Pitfall — overlapping vs touching:** decide whether an interval ending at `t` and one starting at `t` count as overlapping (Meeting Rooms usually says no; some interval-merge variants say yes) — the comparison operator (`<` vs `<=`) flips based on this.
- **Two heaps for server routing:** keep one heap of "free servers" (by id, for tie-breaking) and one of "busy servers" (by free-at time); pop busy→free servers before assigning, don't rescan the whole fleet each request.
