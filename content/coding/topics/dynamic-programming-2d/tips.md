- **Pad with a sentinel row/column.** Sizing the table `(n+1) x (m+1)` and reserving row 0 / column 0 for the "empty string" or "before the grid" base case removes almost all the fiddly index-boundary bugs.
- **Write the recurrence in English first**, then translate: "if the two characters match, extend the diagonal; else take the best of skipping one side." Coding the recurrence before you can state it in words is how off-by-one errors creep in.
- **Fill order matters.** Row-by-row works for alignment and grid problems. Palindrome/interval problems (Palindromic Substrings, Burst Balloons) must fill by **increasing substring length**, since `dp[i][j]` depends on shorter, *inner* ranges.
- **Space optimization:** if `dp[i][j]` only reads row `i-1` (and maybe `dp[i][j-1]`), collapse to one or two 1-D arrays. Watch the iteration direction — 0/1 Knapsack must iterate capacity **right to left** on a 1-D array so each item is used at most once; unbounded variants go left to right.
- **Count vs. optimize:** counting problems (Coin Change II, Distinct Subsequences, Interleaving String) sum contributions from valid transitions; optimization problems (Edit Distance, Min Path Sum) take a min/max. Don't mix `+=` and `min()` logic — decide which the problem wants before coding.
- **Pitfall — empty-string/base-case sign errors:** `dp[0][j] = j` (all inserts) and `dp[i][0] = i` (all deletes) for Edit Distance; getting these backwards silently produces a plausible-looking but wrong table.
- **Pitfall — obstacle/invalid cells:** in grid DP, an obstacle should zero out or block that cell's contribution, not just skip the update — a stale value from a previous row will leak through.
- **Reconstruct the path when asked**, not just the number: walk backward from `dp[n][m]` re-deriving which transition was taken at each step (diagonal vs. up vs. left) instead of storing extra pointers, unless the interviewer wants explicit backtracking.
- **State the complexity:** most of these are O(n·m) time; call out the space optimization explicitly if you apply it — it is a common, low-cost follow-up.
